# VNPyKit 0.1.0 alpha 1

This first public-alpha candidate provides a browser-native Python application
runtime with an allowlisted DOM renderer, controlled accessible form widgets,
protocol v1 validation, a dedicated Pyodide Worker per app, static builds, and a
framework-independent embedding API.

The Node CLI creates starter projects, serves local development over loopback,
and assembles self-contained static deployments with pinned runtime files and
checksums. Plain HTML, React StrictMode, Vue, form submission, and two independent
instances are included in the three-engine acceptance matrix.

This alpha has a deliberately small UI surface. Dynamic tree changes, graphics,
games, arbitrary Python packages, server rendering, and hostile-code isolation
are outside its supported scope. See the compatibility and known-limitations
documents before adopting it.

## Alpha qualification disclosures

VoiceOver with Safari was **NOT RUN** for this alpha. The owner approved a
release waiver, so macOS screen-reader behavior remains an acknowledged,
unverified limitation rather than a passing test result.

Preliminary trademark searches did not establish formal or worldwide legal
clearance. The owner accepted the residual VNPyKit brand-confusion risk for this
alpha without claiming non-infringement or zero risk. The detailed evidence and
scope are recorded in
[`v0.1.0-alpha.1-final-signoff.md`](v0.1.0-alpha.1-final-signoff.md).

Security reports should use GitHub Private Vulnerability Reporting for
`visionnumbers/vnpykit`.

These disclosures were documented after signed tag `v0.1.0a1`. They do not
alter the immutable tagged source or frozen distribution archives and must be
added to the GitHub prerelease description before announcement.
