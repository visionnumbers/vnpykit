# VNPyKit 0.1.0 alpha 1 release plan

Target identities:

- Python: `vnpykit==0.1.0a1`
- npm: `@vnpykit/protocol`, `@vnpykit/renderer`,
  `@vnpykit/runtime-pyodide`, `@vnpykit/embed`, and `@vnpykit/cli`, each
  at `0.1.0-alpha.1`
- executable: `vnpykit`
- Git tag and GitHub release: `v0.1.0a1`
- repository: `visionnumbers/vnpykit`

No step below is authorized by this document. Tagging, pushing, staging,
publishing, changing visibility, or creating a GitHub release requires separate
owner authorization.

## Preparation order

Completed prerequisites are recorded in
`v0.1.0-alpha.1-final-signoff.md`. The repository is public; the security
controls and exact-tag environments are active; the PyPI Pending Trusted
Publisher is owner-confirmed with environment `public-alpha-pypi`; signed tag
`v0.1.0a1` resolves to the verified release commit; and tag-ref dry run
`38280346291` passed all seven artifact hashes without running a publication
job.

1. Merge the post-tag final sign-off documentation through protected `main`.
2. Revalidate npm authentication, organization ownership, and publishing 2FA.
3. Obtain separate upload authorization and perform the interactive npm
   first-publication bootstrap in dependency order. Stop and investigate on the
   first failure.
4. After all five npm packages verify, obtain separate authorization and
   dispatch `release.yml` from `v0.1.0a1` with
   `publish=true`, `publish_npm=false`, and the exact phrase
   `PUBLISH VNPYKIT 0.1.0 ALPHA 1`. This publishes PyPI through OIDC, verifies
   the already bootstrapped npm packages, and creates the GitHub prerelease only
   if every prerequisite succeeds.
5. Before announcement, supplement the GitHub prerelease description with the
   post-tag trademark-risk and VoiceOver/Safari-waiver disclosure. Do not move or
   recreate the signed tag.

## Registry order

1. Perform the npm first-publication bootstrap in dependency order:
   protocol, renderer, runtime-pyodide, embed, CLI. Every command must use
   `--access public --tag alpha`.
2. Verify each npm version, public access, exact repository URL, integrity, and
   `alpha` dist-tag before continuing.
3. Publish Python through the PyPI pending Trusted Publisher and verify project,
   version, file hashes, repository link, and attestations. The same workflow
   verifies all five npm packages before it creates the GitHub prerelease.
4. After all npm packages exist, configure a Trusted Publisher separately on every
   npm package. Configure it only when a follow-up version can validate the new
   connection within npm's two-day expiry window.
5. Prefer stage-only Trusted Publisher permissions when the workflow is migrated
   to `npm stage publish`; otherwise explicitly allow direct `npm publish`.
   Do not grant dist-tag management unless the workflow needs it.
6. Restrict traditional npm publishing to 2FA and disallow tokens after OIDC is
   validated.
7. Create the GitHub prerelease only after both registries have been verified.

For this first alpha, do not set `publish_npm=true`. The npm packages do not yet
have Trusted Publishers, and interactive 2FA belongs in the local owner session.
The workflow's `publish_npm=true` path is reserved for a later release after all
five package-level Trusted Publishers have been configured and validated.

The alpha npm tarballs intentionally omit an explicit provenance request because
the first publication uses interactive 2FA. The source repository is now public;
future npm Trusted Publishing can generate provenance after each package exists
and its publisher is configured.

## Failure response

- PyPI: stop the workflow, yank the affected release, keep the immutable version
  and Git history, and publish a corrected higher version.
- npm: stop before the next dependent package; deprecate the faulty version and
  move the `alpha` dist-tag to a corrected higher version. Use unpublish only
  when npm policy permits and an emergency justifies it; never reuse a version.
- GitHub: do not move or rewrite the signed tag. Withdraw incorrect release
  presentation if necessary, retain evidence, and publish a corrected prerelease
  from a new version/tag.
- Any hash, ownership, OIDC, or permission mismatch is a hard stop.
