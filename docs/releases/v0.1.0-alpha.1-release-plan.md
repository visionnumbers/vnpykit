# VNPyKit 0.1.0 alpha 1 release plan

Target identities:

- Python: `vnpykit==0.1.0a1`
- npm: `@vnpykit/protocol`, `@vnpykit/renderer`,
  `@vnpykit/runtime-pyodide`, `@vnpykit/embed`, and `@vnpykit/cli`, each at
  `0.1.0-alpha.1`
- executable: `vnpykit`
- Git tag and GitHub release: `v0.1.0a1`
- intended repository: `visionnumbers/vnpykit`

## Order of operations

1. Review the release commit and verify a clean checkout.
2. Confirm namespace ownership, legal clearance, security intake, and manual
   accessibility evidence.
3. Create the target public repository and configure branch protection, security
   features, release environments, and required reviewers.
4. Configure PyPI Trusted Publishing for `.github/workflows/release.yml` and the
   `public-alpha-pypi` environment.
5. Establish each npm package and configure its trusted publisher for the same
   repository/workflow and `public-alpha-npm` environment.
6. Create signed tag `v0.1.0a1` on the approved commit and push only with explicit
   authorization.
7. Dispatch the release workflow with the exact tag and `publish=false`; review
   uploaded artifacts and checksums.
8. After final authorization, dispatch with `publish=true`, approve protected
   environments in sequence, verify registry provenance, and verify the GitHub
   release assets.

Rollback for an alpha uses registry deprecation/yanking and a corrective release;
published package files and Git history are never rewritten.
