# VNPyKit 0.1.0 alpha 1 accessibility review

Status: automated gate passed; owner reports Windows checks passed; documented
manual evidence remains incomplete and VoiceOver/Safari is **NOT RUN**.

The release candidate uses semantic form controls, labels, required/invalid
attributes, live status and alert roles, visible focus, keyboard submission, and
focus preservation. The final automated run adds Axe WCAG 2.0/2.1 A/AA rules to
the existing browser interaction coverage.

On 2026-10-11, Chromium 156.0.8078.4 passed the Axe 4.13.0 scan with zero
critical or serious WCAG 2.0/2.1 A/AA violations. The first run correctly found a
serious prohibited-ARIA issue on the demo scratch mount; adding `role="region"`
to its existing `aria-label` fixed the issue, and the rerun passed. The complete
local suite also passed keyboard form submission, focus, validation alerts,
three-engine controlled forms, and independent application ownership.

The first private GitHub CI run on 2026-10-12 found that Linux Chromium resolved
the system `GrayText` color to `#808080`, producing 3.94:1 contrast on white.
VNPyKit replaced it with a Canvas-relative 72% mix and `CanvasText` fallback; the
focused Chromium Axe test then passed. The replacement CI run is the authoritative
cross-platform result.

Manual NVDA/Firefox, VoiceOver/Safari, Windows High Contrast, 200% and 400% zoom,
reduced-motion, and two-instance assistive-technology checks require supported
platforms and human review. They are not inferred from automated tests and remain
release blockers until their versions, findings, and any remediations are logged
in `docs/accessibility-audit.md`.

On 2026-10-12 the owner reported that Windows accessibility checks passed. This
is retained as owner-reported evidence rather than an independent certification
because the browser, assistive-technology versions, transcript, and exact covered
items were not supplied. The owner did not report a macOS test, so the required
VoiceOver/Safari check is **NOT RUN**.
