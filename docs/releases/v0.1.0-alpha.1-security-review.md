# VNPyKit 0.1.0 alpha 1 security review

Status: automated review passed; external security-intake gate remains blocked.

The review covers the complete Git history, tracked-source scanner, dependency
advisories, packaged file lists, absolute paths and source maps, workflow
permissions, license notices, renderer allowlists, protocol limits, path
traversal, loopback defaults, CSP, Worker termination, generation isolation, and
the documented hostile-code boundary.

Current design findings:

- Renderer text uses DOM text properties and an allowlisted component/property
  surface; protocol envelopes and payloads are bounded and validated.
- Each app generation owns a Worker and stale generations are rejected and
  terminated. A same-origin Worker remains explicitly outside the hostile-code
  threat model.
- CLI paths, bases, hosts, wheel selection, and static assembly have negative
  tests. Development serving defaults to loopback.
- The release workflow grants read-only repository access during verification.
  OIDC and write permissions are isolated to protected publication jobs.
- PyPI and npm publication use Trusted Publishing; no long-lived release token is
  designed into the workflow.

Private vulnerability reporting and repository security settings cannot be
enabled until the owner creates the intended remote. That remains a release
blocker.

## Executed evidence

- The repository scanner passed all 144 inspected files.
- Gitleaks 8.30.1 scanned all six commits (about 467 KB) with no findings.
- `pnpm audit --audit-level high` and the independent 46-package consumer both
  reported zero known vulnerabilities; the clean Python environment reported no
  broken requirements and VNPyKit declares no runtime dependencies.
- Twine, wheel-content, and custom nested-archive audits passed. The latter checks
  archive traversal, private/workspace metadata, internal exact versions, stale
  identities, source-map text, and local absolute paths.
- All lifecycle, stale-generation, renderer, protocol, traversal, CSP, loopback,
  and static-assembly test gates passed in the release suites.
- Actionlint 1.7.12 validated both GitHub Actions workflow files.

The workflow uses mutable major action references and PyPA's documented release
branch. Pinning reviewed action commit SHAs is recommended when the owner creates
the remote and can enable Dependabot review. Protected environments and private
vulnerability reporting still require external configuration.
