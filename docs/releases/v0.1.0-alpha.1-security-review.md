# VNPyKit 0.1.0 alpha 1 security review

Status: automated review and live public-repository protection checks passed on
2026-10-13. Residual governance limitations are documented below.

## Design and workflow review

- Protocol messages and payloads are bounded and validated.
- Renderer content uses safe DOM text properties and allowlisted components and
  properties.
- Each app generation owns one Worker; stale generations are rejected and
  terminated. A same-origin Worker is not a hostile-code sandbox.
- CLI path, base, host, wheel, CSP, and static-assembly boundaries have negative
  tests. Development serving defaults to loopback.
- Verification jobs receive read-only repository access. OIDC and repository
  write permissions exist only on separately conditional publication jobs.
- All third-party GitHub Actions are pinned to reviewed immutable SHAs. Runners
  are fixed to `ubuntu-24.04`.
- npm packages default to the `alpha` dist-tag. Explicit npm provenance was
  removed from package metadata because npm does not support provenance for a
  private source repository. Trusted Publishing can generate provenance
  automatically after the source repository is public.
- The release workflow has explicit `publish` and `publish_npm` switches plus
  an exact typed authorization phrase. The false path cannot upload to
  registries or create a GitHub release.

## Live protection state and residual limitations

Live API checks on 2026-10-13 confirmed Private Vulnerability Reporting, secret
scanning, push protection, Dependabot security updates, Actions full-SHA
enforcement, CodeQL default setup, the protected `main` ruleset, and the exact
`v0.1.0a1` tag ruleset. CodeQL completed Actions, Python, and
JavaScript/TypeScript analyses for the release commit.

All three release environments restrict deployment to exact tag `v0.1.0a1`,
use ten-minute wait timers, and disable administrator bypass. They have no
required reviewers. Repository Actions policy still allows all external actions,
although every tracked workflow reference is an immutable full SHA and job
permissions remain least privilege. Adding reviewers and narrowing the allowed
action set are residual hardening opportunities.

Publication still requires the single-owner controlled procedure: verify the
exact tag and hashes, dispatch only after explicit authorization, and verify each
registry result before advancing. No long-lived PyPI or npm automation token is
planned.
