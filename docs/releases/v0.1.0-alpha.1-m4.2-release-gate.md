## PyPI OIDC decision

PyPI's GitHub publisher form makes the environment field optional. Leaving it
blank means matching is based on the configured project, owner, repository, and
workflow without requiring an environment match. The `publish-pypi` job may still
declare `environment: public-alpha-pypi`; this does not make the blank publisher
incompatible.

The security limitation is narrower matching and the absence of a GitHub
approval rule. After the repository becomes public, create
`public-alpha-pypi`, add the required reviewer and prevent self-review where the
plan permits, then replace the blank PyPI publisher with one bound to that exact
environment. Do this before the first upload.

Authoritative references checked on 2026-10-12:

- PyPI, [Creating a project with a Trusted Publisher](https://docs.pypi.org/trusted-publishers/creating-a-project-through-oidc/)
- PyPI, [Adding a publisher](https://docs.pypi.org/trusted-publishers/adding-a-publisher/)
- PyPI, [Trusted Publishing security model](https://docs.pypi.org/trusted-publishers/security-model/)
- GitHub, [Deployment environments](https://docs.github.com/en/actions/reference/workflows-and-actions/deployments-and-environments)
- GitHub, [Private vulnerability reporting](https://docs.github.com/en/code-security/security-advisories/working-with-repository-security-advisories/configuring-private-vulnerability-reporting-for-a-repository)
